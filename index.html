Catatan Belanja

Personal and small-business finance tracker with receipt OCR and AI parsing. Laravel 12, Filament v4, PostgreSQL.

Documentation for version 1.0.0 (October 2026)

Overview

Catatan Belanja records your finances in one place. Upload a photo of a shopping receipt: the text is read automatically (Tesseract OCR) and turned into structured data (vendor, date, category, line items, total, change) by an AI model (Cohere). If the AI service is unavailable or no API key is set, a built-in regex parser takes over automatically.

Beyond expenses, the application records income, debts and receivables with automatic settlement status, monthly budgets with alerts, a cash flow report, Excel/PDF reports, and an "Ask AI" assistant that answers questions about your own data. It is built for two kinds of users: individuals (daily records) and small businesses (multi-user, business expense categories).

Interface language and currency. The application interface is written in Indonesian and amounts are shown in Indonesian Rupiah (Rp). A full English interface is not included in this version. The receipt OCR is configured for Indonesian and English receipts.

Feature list

  • Receipt upload with OCR. Tesseract OCR (Indonesian and English), with automatic image compression (GD) before processing.
  • AI parsing with fallback. Cohere converts OCR text into JSON. If the API fails or no key is configured, the regex parser takes over. The parsing path (AI or estimate) is shown on the detail page.
  • Admin panel (Filament v4). Full CRUD for Expenses (with line items), Income, Debts, Categories and Budgets; receipt photo preview, parsing status badge, automatic polling, and a "re-process OCR and AI" button.
  • Income. Source, amount, date received and notes, with a total income card on the dashboard.
  • Debts and receivables. Debt (money you owe) and receivable (money owed to you) with counterparty, amount and due date. Settlement status (unpaid, partial, paid) is calculated automatically, with "mark as paid" and "record partial payment" actions, dashboard cards, and Excel/PDF export.
  • Categories. Default system categories shared by all users (read-only) plus personal categories per user, with automatic category guessing from vendor and items.
  • Monthly budgets. Per category or overall. Notifications fire when usage reaches 90% and 100% (once per period each) through the Filament notification bell.
  • Reports and cash flow. Date or month filters with category filters, summaries, charts, and Excel/PDF export. The cash flow page shows total income, total expenses and balance, with a monthly chart and breakdown table.
  • Ask AI. A dashboard action for natural-language questions over expenses, income, debts and receivables. Retrieved data is summarized and sent to Cohere with a strict system prompt that discourages invented numbers. A daily per-user limit applies.
  • Multi-user. Every account sees only its own data.
  • Queue monitoring. The dashboard warns when parsing jobs are stuck (queue worker not running), counting only the logged-in user's receipts.
  • Account deletion. Users can delete their own account and all associated data after email and password verification.

How receipt processing works

Photo upload -> OCR (Tesseract) -> try AI parsing (Cohere)
                                     |-- success -> structured data
                                     |-- API failure/timeout -> regex fallback
                                  -> PostgreSQL -> notification, dashboard, reports

Requirements

  • PHP 8.2 or newer with the extensions pdo_pgsql, gd and mbstring
  • Composer, and Node.js with npm
  • PostgreSQL 13 or newer. PostgreSQL is the only database this application was built and tested on. MySQL and MariaDB have not been tested and are not guaranteed to work.
  • Tesseract OCR installed on the server, with language data for ind and eng. This is a system program, not a PHP package.
  • A queue worker that keeps running (Supervisor, systemd or Task Scheduler). Without it, uploaded receipts are never processed.
  • A Cohere API key (optional). Without a key, receipt parsing still works through the fallback parser, but the Ask AI feature cannot answer.
  • The pcntl extension on Linux/macOS (optional). It is only needed for the log viewer slot of composer run dev; on Windows that slot is skipped automatically.

Hosting. Shared hosting (cPanel) is usually not suitable: it typically does not provide PostgreSQL, does not allow installing Tesseract, and does not keep a worker running. A VPS, or any host that allows all three, is recommended. The application was developed and tested on Windows (Laragon). Deployment on Linux follows standard Laravel practice, but your server may need adjustments.

Installing Tesseract

  • Windows: use the UB-Mannheim installer and tick both the Indonesian and English language packs, or copy ind.traineddata and eng.traineddata into C:\Program Files\Tesseract-OCR\tessdata.
  • Ubuntu/Debian: apt install tesseract-ocr tesseract-ocr-ind

Verify with tesseract --list-langs. The output must include ind and eng.

Installation

  1. Install dependencies:

    composer install
npm install && npm run build

    npm install is required even if you do not use Vite, because composer run dev relies on npx concurrently, which comes from npm install.

  2. Copy .env.example to .env and edit it:

    DB_CONNECTION=pgsql
DB_HOST=127.0.0.1
DB_PORT=5432
DB_DATABASE=catatan_belanja
DB_USERNAME=...
DB_PASSWORD=...
COHERE_API_KEY=                    # optional
COHERE_MODEL=command-a-03-2025     # default model for receipt parsing
COHERE_INSIGHT_MODEL=              # optional model for Ask AI
AI_INSIGHT_DAILY_LIMIT=10          # Ask AI questions per user per day
APP_DEBUG=false                    # must be false in production

    Then generate the application key:

    php artisan key:generate

  3. Run migrations and the seeder (creates one admin account and the default categories):

    php artisan migrate
php artisan db:seed

    Change the seeded password. The seeded account uses a weak, publicly known password (test@example.com / password). On any server reachable by other people, change the password or delete that account and register a new one right after seeding.

  4. Create the storage symlink for public assets:

    php artisan storage:link

  5. Start the queue worker. Receipts are processed by a queued job (AIParserJob), not during the web request. If the worker is not running, receipts are saved but vendor, total and items are never filled in.

    php artisan queue:work --timeout=150

    Run it in a separate terminal, or register it with Supervisor, systemd or Task Scheduler so it restarts after a server reboot. See Running the application for the timeout rules.

The admin panel is available at /admin.

Running the application

The queue worker must be running. OCR and AI parsing run asynchronously. Without a worker, parsing results are never filled in.

One command for development

composer run dev starts everything in one terminal:

SlotProcessPurpose
serverphp artisan serveHTTP server at http://127.0.0.1:8000
queuephp artisan queue:work --tries=1 --timeout=150Queue worker (required)
logsphp artisan dev:logsReal-time log viewer (forwards to php artisan pail when pcntl is available)
vitenpm run devAsset hot-reload at http://localhost:5173

On Windows the log slot prints a notice that Pail needs pcntl and exits cleanly without affecting the other slots. Press Ctrl+C to stop everything.

The queue worker keeps a PHP process alive. After changing anything under app/Jobs or app/Services, restart composer run dev or run php artisan queue:restart.

Manual mode

Use this if composer run dev fails in your environment (for example Windows without Node.js).

php artisan serve                      # terminal 1
php artisan queue:work --timeout=150   # terminal 2 (required)
npm run dev                            # terminal 3 (optional, hot reload)

Useful commands:

php artisan queue:restart       # restart workers after a deploy
php artisan queue:failed        # list failed jobs
php artisan queue:retry all     # retry failed jobs

Sync mode. With QUEUE_CONNECTION=sync no worker is needed; parsing runs during the upload request. The upload request becomes slower because it waits for OCR and AI to finish. This suits personal use and development.

Queue timeout rules

Three numbers must stay in this order. Breaking the order makes a job run twice, which is hard to notice because the parsed result looks correct: you only see duplicated notifications, items deleted and recreated by two processes, and double API calls.

job timeout (150)  <=  worker --timeout (150)  <  retry_after (180)
AIParserJob::$timeout     queue:work argument      config/queue.php
ValueWhereMeaning
150app/Jobs/AIParserJob.php ($timeout)Maximum time of one job. Exceeding it counts as a failure and the job is retried.
150--timeout argument of queue:workMaximum time of the worker child process. Must be at least the job timeout, otherwise the worker kills the job early. Laravel's default is only 60 seconds.
180config/queue.php (retry_after)How long Laravel waits before assuming a job is lost and handing it to another worker. Must be greater than the job timeout.

The default in config/queue.php is already 180, so nothing needs to be set in .env. The only thing you must remember is the --timeout=150 argument when you start a worker yourself. It is already included in composer run dev.

Cohere API key

The key is optional. Without it, receipt parsing uses the fallback parser, and only the Ask AI feature stops working.

  1. Go to dashboard.cohere.com and create an account (Google or GitHub sign-in works; no credit card is required for a trial key).
  2. Open the "API Keys" menu. Cohere creates a free trial key named "default".
  3. Copy the key into your .env file: COHERE_API_KEY=your_key_here.
  4. Never commit or share your .env file. It is ignored by Git in this project.

Trial keys are for testing. A trial key is free and limited (about 1,000 API calls per month) and may not be used for commercial or production applications with many users. For production, use a paid production key (see Cohere's pricing page).

No key is bundled. This package intentionally contains no API key. You create your own key and pay your own usage. Sharing someone else's key exhausts the quota quickly and makes the application look broken when the code is fine.

Model and cost. The default model command-a-03-2025 is accurate but costs more per token. To reduce cost, set COHERE_MODEL=command-r7b-12-2024. All API costs are paid by the key owner.

Resilience. If Cohere is unreachable, the key is missing, or the trial limit is reached, receipt parsing falls back to the built-in pattern-based parser, so receipt recording, reports, budgets and debts keep working.

User guide

Menu names below are shown as they appear in the interface (partly Indonesian).

Dashboard

The start page shows summary cards (total expenses, number of transactions, average per transaction, total income, active debts, active receivables) and a history chart. The Tanya AI (Ask AI) button at the top right opens the question box. A warning appears if receipts are stuck in processing.

Laporan (Reports)

Choose a date range or a month, then optionally one or more categories. The page shows a summary, a category chart and a transaction table. Use the export buttons for Excel or PDF.

Expenses

The main recording menu. There are two ways to add data:

  1. From a receipt: click add and upload a receipt image (maximum 5 MB). The image is compressed, read by OCR and parsed in the background. After a few seconds the vendor, date, category, items and total are filled in, and a notification appears in the bell. Review the result through the "Periksa & Edit" link.
  2. Manually: enter vendor, total, date and items without a photo.

The detail page has a re-process OCR and AI button for results that need another try. A badge and polling in the list show receipts that are still processing, and the parsing path (AI or estimate) is shown on the detail page.

Categories

Default categories are shared and cannot be deleted. For a default category you can only change its appearance (color and icon) for your own account. You can also create personal categories that only you can see.

Budgets

Set a monthly spending limit, per category or overall. The "Terpakai" (used) column shows usage for the period. Notifications fire at 90% and 100% usage, once each per period. Only one budget is allowed per category, month and year combination.

Utang Piutang (Debts and receivables)

Choose the type (utang = you owe, piutang = someone owes you), then enter the counterparty, amount and due date. The status (unpaid, partial, paid) is calculated automatically. Use Catat Pembayaran Sebagian (record partial payment) or Tandai Lunas (mark as paid). The list can be filtered (including by due date) and exported to Excel or PDF.

Pemasukan (Income)

Record money received: source, amount, date received and notes. Totals appear on the dashboard and feed the cash flow page and Ask AI.

Kas Arus (Cash flow)

Income versus expenses and the balance for the selected period, with a monthly chart and a detail table. Exportable to Excel and PDF.

Tanya AI (Ask AI)

Type a question in Indonesian (up to 2,000 characters), for example "How much did I spend last month?" or "How much debt do I have left?". The system retrieves the relevant data and asks Cohere to summarize it. A daily per-user limit applies (AI_INSIGHT_DAILY_LIMIT). A COHERE_API_KEY is required. AI answers can be wrong, so check them against the data in the related menus.

Profile and account

Edit account details, or delete the account. Deletion is permanent and removes everything owned by the account: expenses, income, debts and receivables, budgets, personal categories and notifications.

Customization

These are the supported ways to adjust the application without changing its structure.

  • AI models and limits. Set COHERE_MODEL, COHERE_INSIGHT_MODEL and AI_INSIGHT_DAILY_LIMIT in .env. To lower AI cost, use command-r7b-12-2024 as the model. Run php artisan optimize:clear after changing .env.
  • Disable public registration. Remove or comment out the ->registration(Register::class) line in app/Providers/Filament/AdminPanelProvider.php. Existing accounts keep working. This is the recommended way to limit the application to a single user or a closed group.
  • Default categories. The default (shared) categories are created by the database seeder (php artisan db:seed) from the category seeder under database/seeders. Edit that seeder to change the starting set. Each user can also add personal categories and change the appearance of default ones in the interface.
  • Queue driver and workers. Switch QUEUE_CONNECTION between database, redis and sync in .env, and follow the timeout rules in Running the application. For heavier traffic see Scaling up.
  • Interface language. Interface text is written in Indonesian inside the application code and amounts are shown in Rupiah. A translation or a different currency format is not included; changing them means editing those strings in the application code.

Before you extend the code. Read Security notes first. In particular, queries in console commands and queued jobs need an explicit user_id filter, category queries need their own filter, and adding a role system is not a small change.

Production checklist

Environment

  • APP_ENV=production
  • APP_DEBUG=false
  • APP_URL matches your real domain
  • LOG_LEVEL=info (not debug)
  • SESSION_ENCRYPT=true
  • SESSION_SECURE_COOKIE=true only when served over HTTPS
  • Database credentials for a regular user, not root or a superuser
  • COHERE_API_KEY set to your own key, or left empty if you do not use AI
  • The seeded account's password changed, or the account deleted
  • MAIL_* configured if you want password reset emails

Code and assets

  • composer install --no-dev --optimize-autoloader
  • npm install && npm run build (not npm run dev; without a build the panel has no CSS)
  • php artisan migrate --force
  • php artisan storage:link
  • Web server document root pointed at public/, never the project root
  • storage/ and bootstrap/cache/ writable by the web server user

Background services

  • Queue worker running with --timeout=150 under Supervisor, systemd or Task Scheduler
  • php artisan queue:restart after every deploy
  • Worker runs as a non-root account
  • tesseract --list-langs lists ind and eng

After deploying

  • Upload one real receipt and confirm the photo uploads, the notification arrives, and vendor, total and items are filled in
  • Open /admin in a private window and confirm no debug page or error leaks server paths
  • Run php artisan test only on a development or test environment with a separate database. Never run it against a production database: tests can reset or delete data.

Backup and restore

Your data lives on your own server, so backups are your responsibility. Back up two things: the database and the receipt photos.

Database

pg_dump -U <user> -h 127.0.0.1 -Fc -f backup-$(date +%F).dump catatan_belanja

Windows (PowerShell):

pg_dump -U postgres -h 127.0.0.1 -Fc -f backup.dump catatan_belanja

Receipt photos

Copy the folder storage/app/private/receipts.

Restore

pg_restore -U <user> -h 127.0.0.1 -d catatan_belanja --clean --if-exists backup-2026-10-05.dump

Automatic nightly backup (Linux)

Add to crontab -e:

0 2 * * * pg_dump -U <user> -h 127.0.0.1 -Fc -f /path/to/backups/db-$(date +\%F).dump catatan_belanja

Store the database password in ~/.pgpass so the job does not prompt for it.

Test a restore into a separate database before you ever need it. A backup that has never been restored is not proven to work. Excel and PDF exports are reports, not backups: the application has no import feature, so they cannot be restored.

Security notes

  • Authorization uses global scopes, not policies. Per-user isolation is done by the OwnedByUserScope global scope on the Expense, Income, Debt and Budget models, plus query overrides in the Category resource. If you add routes or endpoints outside Filament, add your own authorization checks.
  • Registration is open by default. Anyone can register from the panel. To disable it, remove or comment out the ->registration(Register::class) line in app/Providers/Filament/AdminPanelProvider.php.
  • Single-tier data model; no roles. Every registered account becomes a panel account for its own data and cannot see other accounts. Do not add an "admin role" without also adding a roles table, policies and a management UI: the whole codebase assumes every user owns only their own data. To restrict usage (for example one user for personal use), disable registration instead.
  • Categories have no global scope. The Category model is deliberately left without OwnedByUserScope (see tests/Feature/CategoryUiIsolationTest.php), so every category query must add its own filter: whereNull('user_id')->orWhere('user_id', Auth::id()). A plain Category::find() can return another user's category and must not be used on any page.
  • The scope is inactive without a login. OwnedByUserScope does nothing for unauthenticated contexts (by design, so queues and console commands can process data). Every query in a console command or queued job must therefore use an explicit where('user_id', ...), even if it looks redundant.
  • Logs avoid user data. OCR text, raw AI responses and Ask AI questions are written only at debug level and truncated to 200 characters (App\Support\LogSanitizer). Keep LOG_LEVEL=info in production.
  • Receipt photos are private. They are stored on a private disk (storage/app/private/receipts), not under public/storage, and served only through an authorized route (/receipt-image/{expense}) to the owning user.
  • Credentials belong in .env only and are never committed. .env.example is a clean template.

Privacy and data

  • All financial data is stored in your own PostgreSQL database. Nothing is sent to the seller of this application.
  • OCR runs locally (Tesseract on your server). Receipt photos are not sent to any third party.
  • If COHERE_API_KEY is set, the OCR text is sent to Cohere for parsing, and a summary of the financial data relevant to a question is sent to Cohere for Ask AI. Review Cohere's privacy policy, especially if you handle customer or business data.
  • If COHERE_API_KEY is empty, no data leaves your server for AI services.
  • If you operate the application for other people, you are responsible for complying with the data protection rules that apply to you.

Scaling up

The default setup (database queue, one worker) is more than enough for personal and small-business use. If many users upload receipts at the same time:

  1. Use Redis and several workers. Set QUEUE_CONNECTION=redis and run multiple php artisan queue:work --queue=default --timeout=150 processes, or manage them with Supervisor or Laravel Horizon. With Redis, keep REDIS_QUEUE_RETRY_AFTER above 150 (the default is 180), otherwise jobs that exceed the visibility timeout run twice.
  2. The stuck-queue warning can be normal. One parsing job takes roughly 15 to 45 seconds depending on Cohere's response time. The dashboard warns when a job has waited more than 5 minutes, which is expected during bursts with a single worker. Add workers to reduce it.
  3. Serve built assets. Run npm run build before deploying and enable gzip or brotli compression on the web server.
  4. Later, if data grows very large (thousands of rows per user), consider caching dashboard figures per user.

Upgrading from an older version

If you run an older version where receipt photos still live in storage/app/public/receipts, move them to the private disk:

php artisan receipts:move-to-private-disk

The command is idempotent and verifies each file before removing the old copy.

Tests

php artisan test

The Pest suite (more than 360 tests) covers multi-user scoping, fallback parsing, budgets and notifications, report and export pages, debts, cash flow, Ask AI and the receipt photo route. Run it only against a separate development or test database, never production.
